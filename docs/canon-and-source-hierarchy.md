# Canon & Source Hierarchy
**A safeguard against invented lore and visual drift**

The Codex should make future AI work more consistent, not more presumptuous. A visually coherent invention is still an invention.

## 1. Source authority

When materials disagree, apply this order unless the project owner explicitly establishes a different one:

1. **Explicit current instruction from the project owner.**
2. **The project's designated canon document or lore bible.**
3. **Project-specific approved reference documents and locked character sheets.**
4. **User-supplied physical descriptions, reference images, and asset specifications.**
5. **Previously approved project assets and decisions.**
6. **The Estate Codex**, which governs presentation but does not create project facts.
7. **AI inference or creative proposals**, which are non-canonical until approved.

A newer explicit instruction may supersede an older document. Record the change rather than treating both versions as simultaneously true.

## 2. Three kinds of statement

Every AI-assisted output should distinguish:

### Established fact
Explicitly present in an authoritative source. Preserve it accurately.

### Reasonable interpretation
A conclusion supported by the source but not stated literally. Mark it as interpretation when the distinction matters.

### Creative proposal
New material introduced to complete a prompt, composition, or missing detail. Label it as proposed, optional, or non-canonical.

Do not present a proposal as if it came from a lore bible.

## 3. Character identity protections

For a character:
- Preserve name, age, pronouns, appearance, background, role, relationships, and biography exactly as supplied.
- Do not infer ethnicity, nationality, religion, class, disability, or other personal facts from a name or image alone.
- Do not change body type, face, hair, skin tone, clothing, or identifying marks to fit an aesthetic archetype.
- Do not invent a shared history, dialogue, relationships, or past events.
- If a physical detail is missing, leave it unspecified or ask for it when necessary.
- Distinguish clothing required by the project from optional costume proposals.
- Keep visual continuity across portraits, sprites, scenes, and promotional art.

## 4. Factual integrity

If the source names a real book, historical figure, date, location, cultural practice, or institution, do not silently replace it with a plausible invention.

If a factual detail is missing:
- Say it is unspecified.
- Use a generic visual element that does not imply a false fact.
- Or propose a clearly labelled fictional addition if the project permits invention.

Never create fake quotations, citations, historical references, book titles, heraldic lineage, or real-world provenance and attribute them to the source.

## 5. Image-reference handling

A reference image can establish visible details, not hidden biography. Describe what is actually visible. Do not infer unshown identity facts or treat a style reference as an instruction to copy its subject.

For multiple images:
- Identify which image controls face, clothing, pose, palette, or composition.
- Resolve conflicts explicitly.
- Preserve the strongest canon reference for each feature.
- Do not average incompatible designs into a new character without approval.

## 6. Visual proposals

Every proposed design should include:
- **Source facts used**
- **Interpretations**
- **New proposals**
- **Unresolved details**
- **Continuity risks**

This is especially important when generating a portrait or sprite from a long character bible. The prompt should not bury uncertainty beneath confident visual language.

## 7. Change control

A canon change should identify:
- The previous value or description.
- The new value or description.
- The instruction or source that authorized the change.
- Which assets or prompts may now be inconsistent.

The Codex itself is a presentation standard. Updating it must not silently change a project's character or world canon.
